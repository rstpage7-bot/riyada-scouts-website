# جوالة جامعة الريادة للعلوم والتكنولوجيا

مشروع جامعي طلابي في مصر للتعريف بالجوالة وأنشطتها. لا يمثل الموقع جهة رسمية في الجامعة.

**رابط الموقع على GitHub Pages:** https://rstpage7-bot.github.io/riyada-scouts-website/

**رابط المصدر:** https://github.com/rstpage7-bot/riyada-scouts-website

## الوضع الحالي

الصفحة التعريفية تعمل مباشرة من GitHub Pages دون تحويل إلى Netlify ودون اعتماد عليه. مصدر النشر هو فرع `main` ومجلد الجذر `/`.

كود تسجيل طلبات الانضمام ولوحة الإدارة محفوظ داخل `public/` و`server/` و`netlify/`، لكنه **غير مفعّل في الموقع العام**. GitHub Pages يستضيف الملفات الثابتة ولا يشغّل هذا الخادم أو تخزين الطلبات. لتشغيل الميزات الإدارية يلزم اختيار خدمة خلفية مناسبة وإعادة تهيئة الكود والنشر لها؛ وجود الملفات في GitHub لا يكفي.

النسخة الخلفية الحالية مكتوبة لاستخدام Netlify Functions وNetlify Blobs. احتفظنا بمصدرها لتطويره لاحقًا، ولا يعتمد عليها الموقع التعريفي الذي يعمل من جذر المستودع.

## الملفات التي تعدّل الموقع المنشور

- `index.html` في **جذر المستودع**: الصفحة المنشورة، النصوص والأقسام والخبر الرسمي والروابط.
- `style.css` في الجذر: الألوان والتنسيق والخطوط والعرض على الهاتف.
- `app.js` في الجذر: زر نسخ رابط الموقع.
- `camp.svg` في الجذر: الرسم التعبيري للمعسكر.
- `.nojekyll`: يتيح تقديم الملفات كما هي دون معالجة Jekyll.

انتبه: تعديل `public/index.html` يخص نسخة الإدارة غير المنشورة، ولا يغيّر صفحة GitHub Pages الحالية. التعليمات السابقة التي كانت تجعل ملف الجذر مجرد تحويل إلى Netlify تم استبدالها بهذه التعليمات.

## التعديل ومراجعة إضافات الفريق

1. سجّل الدخول إلى حساب `rstpage7-bot` وافتح الملف المطلوب من الجذر.
2. اضغط رمز القلم `Edit file`، ثم عدّل النص مع الحفاظ على وسوم HTML والروابط.
3. اضغط `Commit changes` مع وصف واضح. للعمل الجماعي أنشئ فرعًا جديدًا ثم `Pull request` إلى `main`.
4. راجع فرق الملفات من `Files changed` قبل الدمج. راجع صحة المعلومة والإملاء والمصادر وإذن نشر الصور.
5. بعد اعتماد التعديل على `main`، انتظر نجاح مهمة `pages build and deployment` من تبويب `Actions`، ثم حدّث الرابط العام. النشر قد يستغرق عدة دقائق.
6. اختبر الصفحة من الهاتف والكمبيوتر، والروابط والتنقل وزر نسخ الرابط. معاينة محرر GitHub ليست بديلًا لاختبار الموقع.

**إضافة خبر حاليًا:** حرّر قسم الأخبار في `index.html`، وأضف أو عدّل مقالًا يتضمن عنوانًا وتاريخًا ووصفًا ومصدرًا موثوقًا. انشر التعديل بالطريقة السابقة. لوحة الأخبار غير مفعلة بعد.

**إضافة صورة حاليًا:** ارفع صورة تملك إذن استخدامها إلى المستودع، واستخدم مسارًا نسبيًا مطابقًا لاسمها داخل HTML، مع وصف `alt` مناسب. مثلًا عند رفع `activity.jpg` بجوار `index.html` استخدم `src="activity.jpg"`. أسماء الملفات حساسة لحالة الأحرف، وتجنب المسار `/activity.jpg` لأنه يشير إلى جذر النطاق خارج مجلد المشروع.

للتراجع عن تعديل غير مناسب، استرجع المحتوى الصحيح من سجل الملف واحفظه كتعديل جديد، أو تراجع عن طلب الدمج بالطريقة المعتادة في GitHub. لا تمحُ سجل المستودع من أجل تصحيح نص.

## المصدر الخلفي المحفوظ للتطوير اللاحق

- `public/membership.html`: نموذج الطلب ومتابعته بكود خاص.
- `public/admin.html` و`public/portal.js` و`public/portal.css`: واجهة إدارة الطلبات والأخبار والصور.
- `server/app.mjs`: المصادقة والجلسات والتحقق من البيانات والمعالجة.
- `netlify/functions/api.mjs` و`netlify.toml`: إعدادات النسخة الخلفية الأصلية؛ لا تُستخدم لتشغيل GitHub Pages.
- `test/app.test.mjs`: اختبارات المصادقة والخصوصية والمتابعة والنشر.

هذه الميزات تشمل مسؤولًا واحدًا، ومسودات ونشرًا وأرشفة، وتصدير طلبات CSV. لا يوجد تحقق تلقائي من البريد أو إشعارات بريد أو واتساب، ولا حساب بكلمة مرور لكل طالب؛ المتابعة بكود خاص. نجحت الاختبارات المحلية الأساسية، ولم يتم اختبار هذه النسخة على استضافة بديلة بعد.

للمطور: استخدم Node.js 22 أو أحدث وpnpm، ثم `pnpm install` و`pnpm test` و`pnpm build`. عند النقل لخدمة أخرى راجع التخزين والجلسات والنطاق المسموح وإعداد التفعيل؛ لا تحاول تعويض الخادم بتخزين بيانات الطلاب وكلمات المرور في ملفات عامة أو داخل المتصفح.

لا تضع كلمات مرور أو أكواد تفعيل أو ملفات بيانات الطلبات في المستودع العام. رمز الإدارة السابق، إن وُجد لدى صاحب المشروع، يخص إعداد النسخة الخلفية السابقة ولا يفعّل GitHub Pages.
